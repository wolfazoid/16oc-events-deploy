# 16OC Event Hub — Phase 1 (Hub Core, Shadow Mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `worker/` into a hub that snapshots Ticketmaster events per 16OC site every 10 minutes and serves them through Ticketmaster-compatible endpoints. It runs in shadow mode (no site uses it yet) until a daily diff against the live widgets is clean for 3 days.

**Architecture:** A cron handler builds one snapshot per site profile (raw TM event objects after that site's rules) and stores it in KV. `/v1/{site}/events.json` and `/v1/{site}/events/{id}.json` answer from the snapshot and accept the same query parameters the widget sends. Venues and classifications pass through to Ticketmaster with edge caching, as the current proxy does. Pure modules (`select`, `query`, `tm`, `snapshot`) are unit-tested in Node; `index.js` only routes.

**Tech Stack:** Cloudflare Workers (ES modules, Cron Triggers, KV), wrangler 3, Node 24 `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-30-16oc-event-hub-transition-design.md` (sections 2, 3 "Phase 1" and 3a).

## Global Constraints

- Site IDs (URL path segment and KV key part): `saltshed`, `thalia`, `emptybottle`, `space`, `cahn`, `sixteenoc`. Promontory is out of scope.
- Cron: `*/10 * * * *`. Event responses: `Cache-Control: public, max-age=300`.
- KV binding `SNAPSHOTS`, keys `snapshot:{site}` and `meta:{site}`.
- Secrets: `TM_KEY_SALTSHED`, `TM_KEY_THALIA`, `TM_KEY_EMPTYBOTTLE`, `TM_KEY_SPACE`, `TM_KEY_DEFAULT`, `ADMIN_TOKEN`. No key in source, fixtures, logs or responses.
- TM calls: ≤ 5 req/s (250 ms between requests from one invocation). Deep paging stops at `size*page < 1000`.
- "Today" means the America/Chicago date, never the Worker's UTC date.
- Hidden statuses: both `canceled` (Ticketmaster) and `cancelled` (TicketWeb). This is the one deliberate change from the old widget.
- Worker modules are ESM under `worker/src/`. Hub tests are `test/hub/*.test.mjs`. Existing CJS tests stay as they are.
- Cloudflare account and the `events.16oncenterchicago.com` subdomain are owned by 16OC. Task 8 is blocked until access is granted. Use the Workers Paid plan, because the free plan's 10 ms CPU limit is too tight for parsing several hundred events per cron run.

## Review Focus

1. **One TM request in a site fails (5xx/timeout) mid-build** → that site keeps its previous snapshot whole and `meta.lastError` records the failure. Other sites still refresh. (Task 4)
2. **TM returns 200 with zero or very few events** (outage that looks like success) → the drop guard refuses to overwrite a snapshot of ≥ 10 events with one under 50% of its size. (Task 4)
3. **First deploy, KV empty or site never built** → `/v1/{site}/events.json` returns 503 JSON, not a crash or an empty list that looks valid. (Task 6)
4. **Multi-venue event where only a later embedded venue matches `venueId`** → it is included, as Ticketmaster does. (Task 5)
5. **A site query exceeds Ticketmaster's 1,000-result paging cap** (16OC all-venues is at 302 today) → `capped: true` is recorded per request and `/health` reports it. (Tasks 3, 6)

**Interfaces:**
- Produces:

  - `findEvent(events, id): TMEvent | null`.

Parameters (exactly those the Salt Shed bundle sends; anything else, e.g. `source`, is ignored):

| Param | Behavior |
|---|---|
| `id` | comma list; keep events whose id is in it |
| `venueId` | comma list; keep if **any** `_embedded.venues[].id` matches |
| `promoterId` | keep if `promoter.id` or any `promoters[].id` matches |
| `keyword` | case-insensitive substring of event name or any attraction name (plain `includes`, no regex) |
| `classificationName` | case-insensitive equality with any segment/genre/subGenre name in `classifications[]` |
| `localStartDateTime` / `localEndDateTime` | compare `localDate + "T" + (localTime \|\| "00:00:00")` as strings, inclusive; undated events excluded when either bound is given |
| `sort` | `date,asc` (default): by start, undated last. `onSaleStartDate,asc`: by `sales.public.startDateTime` ascending, missing last. `onsaleStartDateTime,desc`: descending, missing last |
| `size` / `page` | default 20 / 0; size clamped to 1..200; out-of-range page returns no events with correct totals |
